# Reflect

只在「這次對話真的改變了做法」時執行。一般收尾不需要。

## 篩選：三條都成立才留

1. **六個月後仍然成立**
2. **會改變未來 agent 的行為**
3. **能指向一個具體落地點**：`AGENTS.md`、`docs/`、`.opencode/skills/`、腳本、測試

丟掉：

- 既有文件已經寫清楚的（**先讀那個檔再判斷**）
- 會漂移的細節：SHA、版本號、次數、金額
- 一次性的偶發事件

## 分類

| 類別 | 內容 |
|---|---|
| **Accepted** | 問題 / 提案 / 落地位置 / 形式（文字或結構） |
| **Rejected** | 理由（避免下次重提） |
| **Backlog** | 能用 lint、腳本或檢查取代的，不要寫成文字 |

判斷準則：**發現自己第二次寫同一條指令，就代表它該變成結構，不是第三條文字。**

## 流程

1. 列出候選，先讀落地位置現有內容，去掉重複
2. 輸出三類清單，**等使用者批准**
3. 只改批准過的項目，一次一個檔
4. 不 commit、不開 PR，除非使用者明確要求

## 反模式

- 把整段對話摘要貼進文件（沒人會讀）
- 提出「要更小心」這種無法執行的建議
- 未經批准就改 `AGENTS.md`
- 把「一次發生」寫成規則（至少 2 次才成模式）
